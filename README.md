# Deployment
1. Flash a USB with the installer iso from [Nonguix](https://gitlab.com/nonguix/nonguix#installation-image)
2. Boot from the USB and run through the GUI installer up to the point where you can configure the system definition.
3. Add the linux kernel, initrd microcode, and linux firmware as well as git, ssh, and a browser to make it easier to clone this repo:
```diff
- (use-modules (gnu))
+ (use-modules (gnu)
+              (gnu packages ssh)
+              (gnu packages version-control)
+              (gnu packages package-management)
+              (nongnu packages mozilla)
+              (nongnu packages linux)
+              (nongnu system linux-initrd))
(use-service-modules cups desktop networking ssh xorg)

(operating-system
+ (kernel linux)
+ (initrd microcode-initrd)
+ (firmware (list linux-firmware))
```
Add the imported packages:
```diff
+ (packages (append
+             (list
+               git
+               openssh
+               stow
+               firefox
```
4. Save the file.
5. Open a TTY session with `Ctrl+Alt+F3`.
6. Initialise the system:
```
herd start cow-store /mnt 
guix system init /mnt/etc/config.scm /mnt
```
7. Reboot and pull out the USB.
```
reboot
```
8. Clone this and the home files repo, stow the conifg files, then update Guix:
```
git clone <this repo>
git clone <home files repo>
cd <home files repo>
stow . # This will symlink the channels and shell configs
guix pull
```
9. Update `~/System/config.scm` to use the `bootloader`, `mapped-devices`, `swap-devices`, and `file-system` values generated by the installation. These can be found here: `/etc/config.scm`.
10. Set passwords for root and any other users (otherwise you might get locked out at login):
```
passwd <user>
```
11. Reconfigure the system using the repo config and pass in substitutes as they're not available until after the rebuild:
```
sudo guix archive --authorize < ~/System/nonguix-signing-key.pub
sudo guix system reconfigure ~/System/config.scm --substitute-urls='https://ci.guix.gnu.org https://bordeaux.guix.gnu.org https://substitutes.nonguix.org'
```
You're done! (hopefully)

## Troubleshooting
### Bootloader
After a BIOS update, Guix failed to boot. I'm still not sure why, but this fixed it: https://felsoci.sk/blog/facing-issues-while-installing-guix.html. It seems that sometimes UEFI implementations look for a bootloader in a fallback location, i.e. the removable media path. In case that link dies, here's what I had to do:
1. Load up my installation media to access the terminal.
1. Mount the EFI partition:
```
mount /dev/nvme0n1p1 /mnt
```
1. Create the fallback path and copy in the bootloader like so (make sure you update the name for the copy):
```
cd /mnt/EFI
mkdir boot
cp /Guix/grubx64.efi boot/bootx64.efi
```
1. Reboot. It should work.

### WiFi
WiFi may not be working so try [this](https://wiki.systemcrafters.net/guix/nonguix-installation-guide/#connecting-to-the-internet) or set up DNS by adding the following to `/etc/resolv.conf`:
```
nameserver 1.1.1.1
nameserver 8.8.8.8
```

### Ghostty
I had trouble getting KDE to locate Ghostty automatically, so I needed to add the program manually in the KDE Menu Editor like so:
```
Name: Ghostty
Program: ghostty
```
Then set the icon.

### Discord
Since I pulled in Discord as a flatpak app, I needed to add the flatpak exports to the `XDG_DATA_DIRS` path so KDE could find it. To fix this, I appended the export dirs to my `.zprofile`, but a better way to do it would be to let Guix Home add those lines.

### Packages with Multiple Outputs
Some packages export multiple outputs, e.g. `bind` has `"out"` and `"utils"`. To specify a particular output on the CLI, use this syntax:
```
guix install bind:utils
```
For `operating-system` definitions, provide a list of two items, one being the package and the other being a string specifying the output:
```guile
(use-modules (gnu packages dns))
(operating-system
 ...
  (packages
    (append
      ;; Note that isc-bind is the Guile symbol for the bind package as 'bind' conflicts with the language keyword
      (list (list isc-bind "utils"))
            %base-packages)))
```
See here for more on this: https://guix.gnu.org/manual/1.5.0/en/guix.html#Packages-with-Multiple-Outputs.

## Maintenance
There's not much you need to do honestly. Just keep guix and your packages up to date, and occasionally take out the garbage:
```
# Update guix
guix pull

# Update packages
guix upgrade

# Clean up garbage (if any)
guix gc --collect-garbage
```
